#+title:      测试时该调图像编码器而非文本提示
#+subtitle:   LoRA-TTT: Low-Rank Test-Time Training for Vision-Language Models
#+source:     https://arxiv.org/abs/2502.02069
#+authors:    Yuto Kojima, Jiarui Xu, Xueyan Zou, Xiaolong Wang
#+venue:      arXiv 2025

* 速读

视觉-语言模型（如 CLIP）在测试时遇到分布偏移，主流做法是调文本提示（TPT），但这条路要求每个测试样本都同时跑文本编码器和图像编码器做反向传播，内存大、速度慢，而且调好的提示和特定文本绑定、不可替换。
这篇论文把可调参数从文本提示换到图像编码器上的 LoRA，文本特征可以提前算好存起来，测试时文本编码器整个不需要了。结果是：内存降到原来的几十分之一，运行更快，提示可以自由替换，准确率还更高。
作者还发现熵最小化损失会让模型过度自信，而一个简单的掩码重建损失能避免这个问题。以后做测试时适应，先问该调的是视觉侧还是文本侧，而不是默认调文本。

* 它到底在解决什么

CLIP 这类视觉-语言模型在训练数据和测试数据分布不一致时，零样本分类性能会下降。测试时训练（Test-Time Training, TTT）的思路是：不给标签，只用当前这一个测试样本，临时调一调模型参数，让它更适应这个样本的分布。

主流方法 TPT（Test-time Prompt Tuning）的做法是：把文本提示里的几个 token 设为可学习参数，对测试图像做数据增强得到 64 个视图，选置信度最高的 10%，用边际熵最小化（Marginal Entropy Minimization, MEM）损失反向传播更新这些 token。
这个方法有效，但有一个结构性问题：**它调的是文本侧，所以每次测试都必须把文本编码器留在计算图里**。文本编码器和图像编码器一样大，每个测试样本都要跑两遍编码器再反向传播，内存和速度代价都很高。
更麻烦的是，调好的提示和初始化它的文本绑定——你想换一组提示（比如换成 80 个手工提示的集成，或换成 CoOp 学到的提示），就得重新调一遍。

这在边缘设备或实时流数据场景下几乎不可用。论文从这里出发，问了一个简单的问题：下游任务（分类、检测、分割）都是视觉任务，为什么调的不是图像编码器？

* 它真正看见了什么

核心判断：**把可调参数从文本提示移到图像编码器的 LoRA 上，文本特征就能提前算好存起来，测试时文本编码器整个丢弃。** 这不只省内存——它改变了系统的结构。

#+begin_example
TPT（调文本侧）              LoRA-TTT（调图像侧）
─────────────────           ─────────────────
测试时需要：                  测试时需要：
  图像编码器 ✓                 图像编码器 + LoRA ✓
  文本编码器 ✓（瓶颈）         文本特征（预计算，查表）
  可学习文本提示               可学习 LoRA 参数
                              文本编码器 → 丢弃

提示灵活性：                  提示灵活性：
  与初始化文本绑定              任意替换（预计算新特征即可）
#+end_example

LoRA（Low-Rank Adaptation）在每层 Transformer 的权重矩阵旁并上两个小矩阵 \(A\) 和 \(B\)，前向传播变成 \(h = W_0 x + \gamma B A x\)，只更新 \(A\) 和 \(B\)，原始权重 \(W_0\) 冻住。
论文只在图像编码器最深的 11、12 层加 LoRA，秩为 16，可训练参数仅 0.2M。因为原始权重不动，单实例调完就重置（episodic TTT），不会灾难性遗忘。

但只换调参位置还不够。MEM 损失有个已知副作用：它把预测分布推向极端自信，模型的置信度远超实际准确率（校准误差 ECE 从基线的 4.80 飙到 TPT 的 12.08）。
论文引入一个极简的掩码重建损失：把图像随机遮掉 50% 的 patch，送进编码器，取 class token，和未遮蔽图像的 class token 算均方误差。这个损失不需要解码器，不需要预训练，只要求模型从残缺视觉线索中恢复全局语义。

#+begin_example
损失          效果                        校准(ECE)
──────────────────────────────────────────────────
MEM 损失      熵最小化，推高置信度          12.08（过自信）
MAE 损失      掩码重建，恢复全局语义         5.59（保持基线水平）
两者结合      兼顾适应性和校准             16.49（MEM 主导时仍过自信）
#+end_example

两个关键证据：

1. **准确率**：在 OOD 基准（ImageNet 及 4 个变体）上，LoRA-TTT 比 CLIP 零样本平均高 5.79%，比 TPT 高约 2%；在细粒度基准（10 个数据集）上平均高 1.36%。直
接调图像编码器（不加 LoRA）在细粒度上反而下降——说明不是「调图像编码器」本身有效，而是「LoRA 限制了调参幅度」才防止了遗忘。

2. **效率**：TPT 反向传播需约 6GB 内存，LoRA-TTT 约 0.2GB（可训练参数 0.2M vs TPT 的 2048，但 TPT 的瓶颈是文本编码器本身在计算图里）。运行时间方面，TPT 的前向+优化+二次前向约 0.5 秒/样本，LoRA-TTT 约 0.15 秒。

这些结果在 CLIP-ViT-B/16、单步优化、episodic 重置的条件下成立。论文没有在更大模型或非分类任务上验证。MAE 损失单独使用时在 OOD 上不如 MEM 损失——它的价值主要在细粒度分类和校准上，两者结合才是最优。

* 我能带走什么

以后看到视觉-语言模型的测试时适应问题，先不急着默认调文本提示，而先问：**这个下游任务是视觉任务还是语言任务？如果是视觉任务，调图像侧能不能让文本侧整个预计算掉？**

这个判断的直接用法：如果你的部署场景是边缘设备或流数据，文本编码器的内存和延迟是瓶颈，把可调参数移到图像编码器的 LoRA 上可以把文本编码器从测试时计算中完全移除。
另一个相关用法：如果你需要灵活切换提示（比如 A/B 测试不同提示模板），调图像侧的方法不锁定提示，可以随时换。
