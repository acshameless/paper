#+title:      语言轨迹比标量奖励更会教模型
#+subtitle:   GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning
#+source:     https://arxiv.org/abs/2507.19457
#+authors:    Lakshya A Agrawal, Shangyin Tan, Dilara Soylu, Noah Ziems, Rishi Khare, Krista Opsahl-Ong, Arnav Singhvi, Herumb Shandilya, Michael J Ryan, Meng Jiang, Christopher Potts, Koushik Sen, Alexandros G. Dimakis, Ion Stoica, Dan Klein, Matei Zaharia, Omar Khattab
#+venue:      ICLR 2026 (Oral)

* 速读

RL 方法（如 GRPO）用数万次 rollout 才能让 LLM 学会新任务，但每次 rollout 产生的推理链、工具调用、编译器错误等自然语言轨迹全被压成一个标量奖励扔掉了。
GEPA 让 LLM 直接读自己的执行轨迹和评估反馈，用自然语言反思提取高层规则，再改写 prompt——这比从标量奖励估梯度信息密度高得多。
结果是在六个任务上平均超 GRPO 6%、最多 20%，且只用 1/35 的 rollout。以后预算受限时，先问能不能用语言反馈改 prompt，而不是直接上 RL。

* 它到底在解决什么

一个多跳问答系统跑一次，会产生：第一跳查询、检索到的文档摘要、第二跳查询、最终答案。如果答错了，RL（GRPO）的做法是给这次 rollout 打一个分（比如 0 分），然后用这个标量去估梯度、更新模型权重。
为了学到稳定的策略，通常需要两万四千次 rollout。

问题在于：每次 rollout 的轨迹本身就是自然语言——推理链、工具调用、甚至评估器在给出 0 分之前打印的编译器错误或未满足的约束条件。这些信息 LLM 天然就能读懂，但 RL 把它们全压成一个数字扔掉了。
当每次 rollout 都很贵（API 调用、工具执行、推理预算）且最大的模型根本无法微调权重时，这种浪费就成了瓶颈。

* 它真正看见了什么

语言轨迹本身就是比标量奖励更丰富的学习介质。LLM 不需要从稀疏奖励中反推梯度——它可以直接读自己的执行轨迹，反思"哪里出了问题"，把教训写成新的指令。

GEPA 把这个直觉变成一个循环：

#+begin_example
  ┌───────────────────────────────────┐
  │  从 Pareto 前沿采样一个候选 prompt  │
  └──────────────┬────────────────────┘
                 ▼
  ┌───────────────────────────────────┐
  │  在 minibatch 上执行，收集轨迹      │
  │  (推理链 + 工具调用 + 评估反馈)     │
  └──────────────┬────────────────────┘
                 ▼
  ┌───────────────────────────────────┐
  │  LLM 反思轨迹 → 改写 prompt         │
  └──────────────┬────────────────────┘
                 ▼
  ┌───────────────────────────────────┐
  │  新 prompt 在 minibatch 上改进?     │
  │  是 → 加入候选池，评估 Pareto 集    │
  │  否 → 丢弃                         │
  └──────────────┬────────────────────┘
                 ▼
           回到顶部，直到预算用完
#+end_example

这个循环里有两个设计选择值得注意。第一，反思不只看执行轨迹，还看"评估轨迹"——评估器在算分之前产生的文本（比如编译器报错、未满足的约束列表），这些在标准 RL 里被丢弃，但对 LLM 反思极有价值。
第二，候选选择不是总挑当前最好的（那会陷局部最优），而是维护一个 Pareto 前沿：对每个训练实例记录最高分候选，只保留非被支配的，按"赢了多少题"加权采样。
这个多样性策略在消融实验中贡献了将近一半的提升——贪心选择只有 +6%，Pareto 选择达到 +12%。

证据落在两个判断上：

第一，在 Qwen3 8B 上，GEPA 用 687 次 rollout 在 HotpotQA 上达到 62.3 分，GRPO 用 24000 次只到 43.3 分——少 35 倍的 rollout，高 19 分。六个任务中五个超过 GRPO，平均用 1/10 到 1/35 的预算。

第二，用弱模型 Qwen3-8B 优化的 prompt 直接拿到 GPT-4.1 Mini 上用，仍然 +9%，超过直接在 GPT-4.1 Mini 上优化的 MIPROv2（+5.6%）和 TextGrad（+6.1%）。
这说明 GEPA 学到的是可迁移的高层策略，不是过拟合某个模型的技巧。

但边界清楚：在 AIME（纯数学竞赛推理）上，GRPO 仍然赢（38 vs 32）。当任务的瓶颈是推理能力本身而非指令策略时，权重空间的梯度更新仍有优势。
GEPA+Merge（交叉策略）在 Qwen3 8B 上有时反而降性能，说明何时合并不同进化线仍需研究。

* 我能带走什么

以后看到一个 LLM 系统需要适配新任务、但 rollout 很贵或模型权重不可改时，先不急着上 RL，而先问：这个系统的执行轨迹和评估反馈能不能被 LLM 自己读懂？如果能，用语言反思改 prompt 可能用 1/35 的成本达到更好的效果。

一个额外用法：如果需要在多个模型间迁移优化结果，prompt 级别的优化天然比权重级别的迁移更便携——弱模型上学到的策略能直接搬到强模型上。
