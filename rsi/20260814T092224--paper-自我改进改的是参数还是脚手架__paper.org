#+title:      自我改进改的是参数还是脚手架
#+subtitle:   Self-Improvements in Modern Agentic Systems: A Survey
#+source:     https://arxiv.org/abs/2607.13104
#+authors:    Zhe Ren, Yimeng Chen, Dandan Guo, Guowei Rong, Tonghui Li, R.B. Xiong, Qingfeng Lan, Wenyi Wang, Li Nanbo, Yibo Yang, Mingchen Zhuge, Jürgen Schmidhuber


* 速读

自我改进的 agent 研究在 2023–2026 年井喷，但同一个机制被叫做 self-correction、meta-prompting、self-play 或 self-evolving agent，名字不同、底子一样，没人能放在同一张图上比。
这篇综述把所有方法统一成一个形式：agent 是 (θ, Σ) 的耦合——θ 是模型参数，Σ 是脚手架（提示、记忆、工具、控制逻辑）；自我改进就是一个更新算子，要么改 θ，要么改 Σ，驱动信号只有三类。
所以以后看到任何「自我改进」的论文，先问两个问题：它改的是参数还是脚手架？信号从哪来？这两个答案一确定，方法就归位了。

* 它到底在解决什么

一个具体困惑：2024 年有人做 prompt 自我优化（Promptbreeder），有人做工具自我创建（Voyager），有人做模型自我训练（Self-Rewarding）。
它们都声称「self-improving agent」，但改的东西完全不同——一个改提示文本，一个改工具库，一个改模型权重。
更麻烦的是，self-correction、meta-prompting、self-play 这些标签各自有社区，彼此不引用，机制相似却无法比较。

旧的处理方式是各做各的综述：有人按「evolve what」分类，有人按「evolve when」分类，但都把模型微调和 agent 脚手架当作两个独立话题，没有统一的形式化视角。
结果是：你无法判断 Promptbreeder（改提示）和 Self-Rewarding（改权重）是否在改进同一种东西，也无法判断它们的信号是否可比。

这个困惑的根源是缺少一个公共坐标系：到底「自我改进」改的是什么，以及改进的信号从哪里来。

* 它真正看见了什么

核心判断：**所有自我改进都可以分解为「改什么 × 靠什么信号」的二维问题。**

论文先给 agent 一个形式定义：

#+begin_example
  A_t = (θ_t, Σ_t)

  θ_t  = 基础模型参数
  Σ_t  = (p_t, m_t, T_t, g_t)
         p = 提示/系统指令
         m = 记忆机制及检索/更新策略
         T = 外部工具及调用接口
         g = 控制逻辑（路由、调度、安全约束）
#+end_example

自我改进就是一个更新算子：拿到经验 → 产生更新信号 → 提交到 θ 或 Σ。两条路的速度和稳定性截然不同：

#+begin_example
              改 θ（模型参数）        改 Σ（脚手架）
  ─────────────────────────────────────────────────
  速度        慢（需训练）            快（改文本/代码）
  稳定性      高（跨任务分摊）        低（易过拟合单任务）
  可逆性      低（权重难回滚）        高（文本可版本控制）
  信号来源    示范/评估/探索          同左，但作用于结构
#+end_example

信号只有三类：
1. *内在生成示范*（intrinsic generative demonstrations）——模型自己生成数据自己训
2. *内在评估反馈*（intrinsic evaluative feedback）——模型自己打分、自己批判
3. *外在探索经验*（extrinsic exploratory experience）——从真实或模拟环境交互中学习

这三类信号 × 两条更新路径，就构成了完整分类。
脚手架改进还细分为四个组件：提示优化（标量反馈、定性反馈、种群进化、文本梯度）、记忆（对象、结构、处理）、工具（路由、精炼、创建）、以及全脚手架重写（如 Darwin Gödel Machine、ADAS）。

一个关键历史转折：经典自我改进（如 Gödel Machine、EURISKO）必须在汇编级代码或原始权重空间中搜索可行修改，搜索空间巨大，无法扩展。
现代基础模型用自然语言作为统一的语义介质——改提示就是改一段文本，改工具就是改一段代码——搜索空间骤降，这才让自我改进从理论可能变成工程可行。

论文还指出一个容易被忽视的分层：全脚手架重写（§6.4）是最激进的一类——agent 不只改某个组件，而是重写自己的整个控制逻辑。
Darwin Gödel Machine 让 agent 在运行中搜索更好的 agent 架构；ADAS 把 agent 设计本身编码为可搜索的文本。
这对应了 Schmidhuber 早期自指学习的现代回声：改进机制本身也必须是可改进的。

*分寸*：这是一篇综述，它的贡献是组织事实，不是发现新机制。分类框架的清晰度是它的价值，但框架本身不证明某条路径比另一条更优。
论文对评测的讨论（§8）指出当前领域的一个真实盲点：大多数 benchmark 只测终态性能，不测改进过程——你无法判断性能提升来自真正的能力增长，还是来自对 benchmark 的过拟合。
这个批评有据，但论文没有给出解决方案。

* 我能带走什么

以后看到任何声称「self-improving agent」的工作，先不急着判断它是否真的在自我改进，而先问两个问题：

1. *它改的是 θ 还是 Σ？*——改参数是慢但稳的长期投资，改脚手架是快但脆的短期适配。
2. *改进信号从哪来？*——内在示范、内在评估、还是外在探索？信号来源决定了改进的天花板：纯内在信号容易自我强化（模型越改越像自己），外在信号更可靠但更贵。

一个延伸用法：如果你在设计一个自我改进系统，先想清楚你要改的层在哪——是提示、记忆、工具、还是整个控制逻辑？不同层的改进速度、可逆性和过拟合风险完全不同。
把改进目标定错层，是比改进算法本身更常见的失败模式。
