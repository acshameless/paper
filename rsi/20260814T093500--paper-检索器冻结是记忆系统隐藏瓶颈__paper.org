#+title:      检索器冻结是记忆系统的隐藏瓶颈
#+subtitle:   EVOLVEMEM: Self-Evolving Memory Architecture via AutoResearch for LLM Agents
#+source:     https://arxiv.org/abs/2605.13941
#+authors:    Jiaqi Liu, Xinyu Ye, Peng Xia, Zeyu Zheng, Cihang Xie, Mingyu Ding, Huaxiu Yao

* 速读

LLM agent 的长期记忆系统都在进化存储内容——抽取、去重、遗忘——但检索基础设施（打分权重、融合策略、上下文预算、生成风格）在部署时就冻住了。
问题在于，不同类型的问题需要根本不同的检索策略：事实查询靠关键词精确匹配，时间推理需要时间感知过滤，多跳推理需要查询分解，对抗性名字交换需要剥除人名。
一个冻结的检索配置不可能同时服务所有需求，而且随着记忆从几十条增长到几百条，为小规模校准的策略越来越失配。
EVOLVEMEM 把完整检索配置暴露为一个结构化动作空间，用 LLM 驱动的诊断模块读逐题失败日志、归类根因、提出针对性调整，
再由一个带回归保护和停滞探索的安全更新规则执行——系统在自己的架构上自主跑起了「观察-假设-实验-验证」的研究循环。
从 BM25-only 的 30.5% F1 出发，7 轮自主进化到 54.3%（+78% 相对提升），还发现了三个原始动作空间里不存在的全新配置维度。
以后看到记忆系统表现不好，先问检索器本身是不是冻住的隐藏瓶颈，而不是只去修内容或调单个参数。

* 它到底在解决什么

一个具体的困惑：一个 agent 记忆系统从最简配置出发——只用 BM25 关键词检索，取 top-5，上下文塞 8 条记忆——在 LoCoMo 长对话基准上只能拿 30.5% F1。
它不是不工作，而是不同问题需要根本不同的检索策略，一个冻结配置不可能同时满足：事实查询需要精确关键词匹配，时间问题需要优先最近记忆，多跳问题需要把查询拆成子查询分别搜索，对抗性名字交换问题需要剥除人名后按语义检索。

现有的记忆系统全都没解决这个问题。MemGPT 管理分层存储，Mem0 构建知识图谱，A-MEM 建卡片盒网络，SimpleMem 压缩对话为检索单元——它们都在进化存储内容，
但打分函数、融合权重、上下文预算和答案生成策略在部署后就冻住了。随着存储记忆从几十条增长到几百条异构记录，为小规模校准的检索策略越来越次优，而这种失配只会随时间恶化。

问题的本质是：检索配置不是一个该由人调的超参数集合，而是一个该随记忆规模和查询分布变化而自我适应的对象。但怎么让系统自己发现该改什么？

* 它真正看见了什么

一句人话：**检索基础设施本身应该是一等优化目标，一个读失败日志的 LLM 能驱动它自我进化——甚至发现原始设计里不存在的全新配置维度。**

机制是一个闭环进化循环（AutoResearch），每轮做四件事：

#+begin_example
  ┌─── EVOLVEMEM 进化循环 ──────────────────────────────────┐
  │                                                        │
  │  EVALUATE  跑评估，写逐题原始日志(预测/真值/分数/来源)  │
  │     │                                                  │
  │     ▼                                                  │
  │  DIAGNOSE  LLM 读日志，按失败模式归类根因，提出 Δθ     │
  │     │                                                  │
  │     ▼                                                  │
  │  PROPOSE   结构化调整提案(改哪些参数、改多少)          │
  │     │                                                  │
  │     ▼                                                  │
  │  GUARD     三分支安全更新:                             │
  │     ├─ 回退:  分数下跌 > τ_rev → 回到历史最优          │
  │     ├─ 探索:  连续 2 轮几乎没变 → 加随机扰动           │
  │     └─ 应用:  正常情况 → 施加诊断提案                  │
  │                                                        │
  │  关键: 诊断 LLM 可以提出原动作空间里没有的全新参数      │
  │  → 机制是自扩展的                                      │
  └────────────────────────────────────────────────────────┘
#+end_example

诊断模块的 rubric 按失败模式（检索到错误实体、上下文不足、时间混淆等）而非按 benchmark 写，所以新发现的配置维度无需改 rubric 就能立即使用。
这就是「自扩展」的来源：诊断 LLM 读失败日志后，可以提出原始动作空间里不存在的参数——比如它自己发明了实体交换（entity-swap）、查询分解（query decomposition）
和答案验证（answer verification）三个全新维度。

**关键证据一：进化轨迹显示系统自主发现了三个全新配置维度。** 下面的轨迹从 θ₀（BM25-only）出发，每一轮都完全自主——诊断模块读上一轮的失败日志，提出调整，元分析器按安全规则验证：

#+begin_example
  轮次  类型    自动发现的变化                      F1(%)
  R0    起点    BM25-only, k=5, ctx=8              30.5
  R1    自动    意图规划 + RRF融合                  35.8
  R2    回退    Cat.3加MMR多样性(被自动回退)        34.8
  R3    自动    ★实体交换(对抗名swap)               37.2
  R4    自动    逐类答案风格标志                    38.5
  R5    自动    ★查询分解(多跳Cat.1/4)              38.1
  R6    自动    Cat.3推理子类+Cat.5实体交换扩展     45.4
  R7    自动    ★答案验证+超参扫描+上下文预算调优   54.3
#+end_example

带 ★ 的是诊断 LLM 从失败日志中自己发现的全新维度——不在原始动作空间里。R2 展示了回归保护：提案导致 F1 下降，系统自动回滚。从 30.5% 到 54.3%，+78% 相对提升，全程无人干预。

**关键证据二：进化发现的配置能跨 benchmark 正向迁移，说明捕获的是通用检索原则而非 benchmark 特定技巧。** 在 LoCoMo 上进化 7 轮的配置 C_L 零样本应用到 MemBench，
直接拿到 54.3%（而 MemBench 从零进化的 C_M 是 67.9%）。更有意思的是，从 LoCoMo 先验继续在 MemBench 上进化（C_LM），
达到 79.2%，比从零进化高出 16.6% 相对——同时 LoCoMo 上的 F1 也从 0.543 升到 0.593（+9.2%）。两个 benchmark 上同时提升，是帕累托改进而非灾难性迁移。

**消融验证了诊断模块的价值。** 用随机扰动替换 LLM 诊断模块（动作空间相同），F1 下降 9.63——说明读失败日志确实提供了有意义的信号，不是随机搜索碰运气。
提取质量控制是损害最大的消融项（-23.22），说明记忆质量是下游一切的基础。

适用边界：这些结果在两个 benchmark（LoCoMo、MemBench）上取得，进化是离线的（最多 7 轮），不是实时自适应。MemBench 上鲁棒性维度仍然最弱——失败日志定位到 POST_PROCESSING 类，
相关记忆根本不在存储里，这说明检索层面的调整无法解决覆盖缺口。跨 benchmark 迁移虽然正向，但 LoCoMo→MemBench 的零样本 54.3% 仍远低于原生进化的 67.9%，说明迁移不是完美的。

* 我能带走什么

以后看到 agent 记忆系统表现不好，先不急着判断「内容质量差」或「该换个更强的模型」，而会先问：检索基础设施本身是不是冻住的？如果打分权重、融合策略、上下文预算从部署起就没变过，
那它很可能就是隐藏瓶颈——尤其是当不同类型问题需要根本不同检索策略时。

一个直接相关的用法：在构建 agent 自我改进系统时，把改进对象从「提示词」或「存储内容」扩展到「检索配置」，并把检索配置暴露为结构化动作空间，让一个读失败日志的 LLM 驱动它自主进化。
关键不是预设所有可调参数，而是让诊断模块能提出设计者没想到的新维度——机制的「自扩展」比预设空间的穷举更接近真正的研究过程。
