#+subtitle:   SIA: Self Improving AI with Harness & Weight Updates
#+source:     https://arxiv.org/abs/2605.27276
#+authors:    Prannay Hebbar, Yogendra Manawat, Samuel Verboomen, Alesia Ivanova, Selvam Palanimalai, Kunal Bhatia, Vignesh Baskaran

* 速读

自我改进 AI 的研究分成两个从不交流的阵营：一边只改 agent 的脚手架（提示、工具、重试逻辑），一边只用 RL 改模型权重。各自都会撞墙——脚手架改不出领域直觉，权重训练改不出搜索策略。
SIA 让一个 Feedback-Agent 根据执行轨迹动态选择拨哪个杠杆，在法律分类、GPU 内核优化、单细胞 RNA 降噪三个领域都突破了只改脚手架的天花板。
关键洞见：harness 和 weights 是两个正交的改变空间，harness 塑造 agent 怎么搜索，weights 改变模型知道什么。

* 它到底在解决什么

想象你在反复改一个 agent 的脚手架——调整提示、加工具、改重试逻辑。前几轮确实有效，但改到某个点就再也上不去了。你觉得是脚手架还不够好，于是继续改。
但其实问题不在脚手架：模型缺少一种领域知识，而这种知识没法写进任何提示或工具里。

这正是自我改进 AI 研究的现状。两条路线各自为战：harness 更新派用一个 meta-agent 重写脚手架，权重冻结；测试时训练派用 RL 更新模型权重，脚手架冻结。
论文的对比表说得很直白：现有的十几个系统——从 Darwin Gödel Machine 到 TTRL——要么只改 harness，要么只改 weights，没有一个同时改两者。两条路线各自撞墙，但谁也不借对方的杠杆。

* 它真正看见了什么

harness 更新和 weights 更新触及的是两个正交的能力空间——harness 塑造 agent 怎么搜索（外部基础设施），weights 改变模型知道什么（内部知识）。一个 Feedback-Agent 可以根据执行轨迹动态选择何时拨哪个杠杆。

       (脚手架进化)               (LoRA适配器进化)
       权重 θ 不变                脚手架 A 不变
            |                          |
     外部化改变                    内部化知识
   工具·解析器·重试·搜索          领域模式·不变量
#+end_example

三个任务的消融实验清楚显示了两个杠杆各自的贡献：

| 任务 | SIA-H（仅 harness） | SIA-W+H（+权重） | 权重额外带来了什么 |
|---|---|---|---|
| LawBench（准确率） | 50.0% | 70.1% | 191 类罪名细分辨析 |
| TriMul 内核（运行时间） | 12,483 μs | 1,017 μs | H100 专用 kernel 设计模式 |
| RNA 降噪（mse_norm） | 0.241 | 0.289 | np.clip+np.rint 生物不变量 |

最说明问题的是降噪任务：
在所有 harness 迭代中，脚手架从未生成过一个把填补后的计数取整为非负整数的后处理步骤——但第一个权重更新 checkpoint 就自发产生了这个两行代码的结构不变量。
harness 改了十几轮都没碰到的领域约束，权重训练一步就内化了。

在 LawBench 上，harness 更新把准确率从 13.5% 拉到 50.0%（搭了 TF-IDF + SVC 的 pipeline），但再怎么调脚手架也上不去了。
权重训练用 PPO 直接在 191 类罪名上施加梯度压力，把模型对相邻罪名的辨析能力磨了进去，又涨了 20 个百分点。
在 TriMul 上，harness 更新写了能跑的 CUDA kernel，但权重训练才让模型内化了共享内存分块、寄存器累积这些 H100 特定的设计模式，运行时间从 12,483 μs 降到 1,017 μs。

这些结果在三个差异极大的领域（法律、系统、生物）一致成立，较稳地显示两个杠杆的正交性不是单一任务的偶然。

需要注意：所有改进都对着同一个固定验证器优化。论文自己指出了「耦合 Goodhart」风险——harness 搜索和权重更新互相塑造对方看到的数据分布，联合不动点是对验证器过拟合的 Nash 均衡，换一个验证器可能就脆。
三个任务的跨领域一致性部分缓解了这一担忧，但没有做分布外验证。

* 我能带走什么

以后看到 agent 改进停滞，我先不急着继续改脚手架，而会先问：当前卡住的是搜索策略（怎么找答案），还是领域知识（知道什么）？如果是后者，再改 prompt 或工具也推不动——需要的是权重更新。

一个直接相关的用法：在构建 agent 系统时，不要把 harness 迭代和模型微调当成二选一的路线选择，而应让一个控制器根据执行轨迹动态切换——harness 先搭好搜索框架，等它饱和后让权重训练补上领域直觉。
