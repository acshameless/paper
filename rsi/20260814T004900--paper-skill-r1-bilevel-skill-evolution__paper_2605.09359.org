#+title:      改技能要奖励跨代进步，不只看单次成败
#+subtitle:   Skill-R1: Agent Skill Evolution via Reinforcement Learning
#+source:     https://arxiv.org/abs/2605.09359
#+authors:    Yash Vishe, Rohan Surana, Xunyi Jiang, Zihan Huang, Xintong Li, Nikki Lijing Kuang, Tong Yu, Ryan A. Rossi, Jingbo Shang, Julian McAuley, Junda Wu


* 速读

你有一个冻结的任务模型（比如 GPT-4o-mini），在多步推理任务上表现很差（GAIA 只有 6.1%）。
你给它配了「技能」（自然语言操作指南），但改进技能要么靠 prompt 工程师手调，要么靠微调任务模型——前者不与下游奖励对齐，后者对闭源模型不可行。

Skill-R1 的洞见是：技能改进本质上是一个跨代递归优化问题，而标准 GRPO 只在同一代内比较 rollout 好坏，看不见「修订本身是否让技能变好了」。
它引入一个跨代优势项，直接奖励让平均奖励上升的技能修订，训练一个轻量技能编辑器（Qwen3-4B），任务模型始终冻结。
在 GAIA 上从 29.7%（标准 GRPO）提升到 41.8%，最难的任务（Level 3）从 15.4% 提升到 38.5%。

* 它到底在解决什么

GPT-4o-mini 在 GAIA 上只有 6.1% 准确率。它不是不会推理，而是缺乏结构化的操作程序——什么时候分解任务、什么时候调用工具、怎么验证中间结果。你可以给它一段「技能」文本作为操作指南，效果立刻提升。但技能本身需要改进。

原来的做法有两类。
第一类是 prompt 工程 / 单轮自我精炼：让 LLM 自己看 rollout 结果然后改技能。问题是这不与下游奖励对齐——LLM 改技能的依据是「看起来合理」，不是「实际提升了验证奖励」。
第二类是微调任务模型：把技能内化到任务模型参数里。对闭源模型不可行，对开源模型计算昂贵且适应性差。

更关键的是，这两种做法都把技能改进当成一次性编辑。
但技能改进是递归的：第一轮技能诱导出一批 rollout，有些成功有些失败；第二轮修订应该从这些成败中提取信号，生成更好的技能；第三轮又基于第二轮的结果继续改进。
标准 GRPO 只在同一代内比较 rollout，告诉你「同一个技能下哪些 rollout 更好」，但看不见「修订后的技能是否比上一版更好」。

* 它真正看见了什么

技能改进需要双层信用分配：同一代内比较 rollout 质量，跨代比较技能修订是否带来进步。

核心关系式：

A = A_intra + λ · A_inter

- = r_g^(i) − mean(r_g)：同一技能下，某个 rollout 相对于同组平均的好坏。这和标准 GRPO 一样。
- = mean(r_g) − mean(r_{g-1})：这一代技能的平均奖励减去上一代。正值说明修订让技能变好了，负值说明退步了。

A_intra 告诉编辑器「哪些 rollout 值得学习」，A_inter 告诉编辑器「你的修订方向对不对」。没有 A_inter，编辑器只知道同一代内谁好谁坏，但不知道跨代是否在进步——它可能在原地打转。

#+begin_example
  Gen g-1              Gen g               Gen g+1
  ┌────────┐          ┌────────┐          ┌────────┐
  │ s_{g-1}│─────────→│  s_g   │─────────→│ s_{g+1}│
  └───┬────┘          └───┬────┘          └───┬────┘
      │                   │                   │
  K rollouts          K rollouts          K rollouts
      │                   │                   │
  rewards r̄_{g-1}    rewards r̄_g        rewards r_{g+1}
      │                   │
      │←─ A_inter ───────→│  (跨代进步)
      │                   │
      │  A_intra: 同代内   │
      │  r_g^(i) − r̄_g    │
      │                   │
      └──→ H_{g-1} ──────→├──→ H_g ──────────→ (历史条件下一轮)
#+end_example

训练只更新技能编辑器（Qwen3-4B），任务模型（GPT-4o-mini）始终冻结。编辑器接收任务上下文、历史 rollout 及其验证结果，生成下一版技能。

证据一：GAIA 上，Skill-R1 (GRPO) 达到 41.8%，比标准 GRPO（29.7%）高 12.1 个百分点。增益在最难的任务上最大——Level 3 从 0%（无技能）→ 15.4%（标准 GRPO）→ 38.5%（Skill-R1）。
这较稳地显示了跨代优势信号在复杂多步任务上的价值。

证据二：PDB 技能的定性对比，清楚展示了「有奖励训练」和「无奖励推理」的编辑器差别。

没有奖励信号训练，编辑器会过拟合到偶然上下文；有奖励信号，编辑器学会保留可迁移结构、抑制噪声。

证据三：跨代进展曲线。第 1→3 代增益最大（奖励从 0.06 升到 0.44，准确率从 9.3% 升到 50%），第 4→5 代趋于平台期，但奖励仍在提升而准确率提升放缓——说明后期代主要提升一致性（同一任务被可靠解决的概率），而非解锁新能力。

这些结果在 GAIA 和 WebWalker 两个 benchmark 上成立，但都使用 GPT-4o-mini 作为任务模型、Qwen3-4B 作为编辑器。更大或更小的模型组合是否表现一致，论文未检验。

* 我能带走什么

以后看到「冻结模型 + 外部技能」的设置，先不急着用 prompt 工程或单轮自我精炼改技能，而问：技能改进是递归的吗？如果是，我需要的不只是「同一轮内谁好谁坏」的信号，还需要「这一版比上一版好吗」的跨代信号。

一个相关用法：这个双层分解不限于技能编辑。任何「生成器产出条件，执行器在条件下执行，结果反馈给生成器」的递归设置——比如 prompt 优化、工具配置选择、检索策略调优——都可以套用 A_intra + λ·A_inter 的框架。
