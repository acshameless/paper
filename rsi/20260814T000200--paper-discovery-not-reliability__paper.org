#+title:      能发现不等于能可靠改进
#+subtitle:   RSIBench-Data: Benchmarking Data-Centric Research for Recursive Self-Improvement
#+source:     https://arxiv.org/abs/2607.25886
#+authors:    Fanqing Meng, Lingxiao Du, Qiguang Chen, Ziqi Zhao, Haocheng Lu, Mengkang Hu, Michael Qizhe Shieh
#+venue:      arXiv 2026 (Evolvent AI / NUS)

* 速读

递归自我改进要求 agent 能把模型失败的证据变成更好的训练数据策略，再训练、看反馈、修正——这个闭环能不能自动跑？
RSIBench-Data 把训练、推理、评测全部固定，只让 agent 变训练数据策略，从而第一次把"研究能力"从基础设施里隔离出来。
结果发现一个发现-可靠性鸿沟：agent 在 58% 的设置里确实能通过迭代发现比第一次更好的策略，但在到达峰值后继续搜索的 23 个设置中，78% 以更低的分数收场，其余只回到同一个峰值。
agent 能偶然发现好策略，但不能稳定地把反馈转化为改进。

* 它到底在解决什么

一个 agent 跑了好几轮，中途找到一个不错的训练数据策略，checkpoint 得分明显提升。然后它继续根据反馈"改进"策略——但后面的尝试反而更差了。
最终提交的 checkpoint 之所以还行，只是因为系统保留了历史最佳，不是因为 agent 真的越改越好。

这个现象之前看不见，因为现有 benchmark 把研究决策和基础设施、优化、评测全搅在一起。agent 跑出好分数或差分数，你分不清是数据策略选对了，还是训练配置不同、评测环境不同、甚至模型都不一样。研究能力被淹没在一堆变量里。

RSIBench-Data 的做法是固定一切——同一个目标模型（Qwen3.5-35B-A3B-Base）、同一个 LoRA SFT 训练后端（Tinker）、同一个推理路径、同一个 Harbor+E2B 沙箱评测、同一个预算——只让 agent 做一件事：决定训练数据是什么。
这样，checkpoint 之间的差异只能归因于 agent 的数据策略研究能力，而不是别的。

* 它真正看见了什么

agent 的数据研究能力可以拆成两半：发现能力和可靠性。发现能力指能不能找到一个比起点更好的训练数据策略；可靠性指能不能在拿到反馈后稳定地改进。这两件事不是一回事。

证据是两个数字：

- 14/24 个设置里，后面的候选确实比第一个有效候选得分更高——发现能力存在。
- 但在到达峰值后继续搜索的 23 个设置里，18 个以更低的分数结束，剩下 5 个只回到同一个峰值——可靠性几乎不存在。

这个非单调性意味着：agent 拿到反馈后，并不总是能把它变成更好的训练数据策略。有时第一次尝试就是最强的；有时中途改进了，但后续修正反而退化。历史最佳选择机制能保住已发现的峰值不被后续退化覆盖，但它并不能让研究过程本身变得可靠。

轨迹分析还发现强 run 的四个共同模式：准确诊断能力缺口、用可执行验证信号而非模型自判来筛选数据、监督信号与评测行为对齐、保留强 checkpoint。这些是发现能力的组成部分，但它们并不能自动保证可靠性。论文也诚实说明这些是过程级观察，不是单因子因果实验。

一个边界：每个设置只跑了一次代表性 run，选择反馈和官方评测用的是同一批任务子集，所以分数衡量的是在新环境中的表现，但不能说明策略能泛化到统计上独立的留出任务。
另外，"研究者身份"把底层 LLM、agent 脚手架和推理强度打包在一起，主矩阵比较的是完整的研究者系统，不是单个组件。

* 我能带走什么

以后看到 agent 在多轮搜索中"改进了"，先不急着判断它有可靠的研究能力，而会先问：它的最终尝试是否真的比峰值更高，还是只是靠历史最佳选择保住了早期发现？

一个相关用法：评估自动 post-training 系统时，不要只看最终分数，要看搜索轨迹的单调性——峰值出现在第几轮、峰值后花了多少钱、最终尝试是否退化。这些过程指标比一个分数更能暴露研究能力的真实水平。
