* 速读

合成数据生成长期以来的做法是"生成一批、过滤一遍"，从不关心生成的题对目标模型来说到底太难还是太容易。
Autodata 把数据创建变成一个 agent 迭代循环：生成题目 → 让弱模型和强模型都试做 → 判断难度是否合适 → 反馈给生成器修改 → 再试。
在 CS 研究任务上，标准方法生成的题太简单（弱模型和强模型得分差只有 0.02），agentic loop 把差距拉到 0.31；在法律任务上，标准方法生成的题太难（弱模型几乎全零，没有学习信号），agentic loop 把弱模型得分从 0.16 提到 0.28、方差从 7.9 提到 12.6。
两个任务方向相反，但结果一样：用 agentic 数据训练的模型全面胜出，法律任务上 4B 模型甚至超过了 397B 基线。核心洞见是：好数据不是更难的数据，而是难度"刚好能学"的数据。

* 它到底在解决什么

假设你要训练一个 4B 模型让它更会做 CS 研究题。你用标准的 Self-Instruct 方法（给 LLM 一个 prompt，让它从论文生成问答对）造了一批数据，然后拿去训。
结果发现：4B 模型本来就能答对 67% 的题，397B 模型答对 69%，差距只有 2 个百分点。这意味着这些题对 4B 模型来说几乎没有学习空间——它已经会了，RL 训练拿不到有效梯度。

换一个场景，你在法律推理任务上做同样的事。这次反过来：标准方法生成的题，4B 模型平均得分只有 15.9%，大量 rollouts 直接得零分。
看起来题很难、gap 很大（55.8 个百分点），应该很适合训练？但 GRPO 需要同一个 prompt 的多次 rollout 之间有得分方差才能产生 advantage 信号——全零的 rollouts 方差为零，模型什么也学不到。

这就是问题所在：现有的合成数据方法只管"生成 + 过滤"，从不检查数据对目标模型的实际学习价值。在 CS 上太容易，在法律上太难，但两种失败都让 RL 训练白费算力。

* 它真正看见了什么

数据质量不等于数据难度。对训练有用的数据，是难度恰好落在目标模型的"可攀爬区间"——弱模型做不好但不是全零，强模型做得好，两者之间的差距提供了有效的学习信号。

Autodata 的做法是让一个 agent 扮演数据科学家，跑一个迭代循环。它的具体实现（Agentic Self-Instruct）有四个子 agent：challenger 生成题目，weak solver 和 strong solver 分别试做，judge 评估质量并给出反馈。
主 agent 根据 judge 的反馈修改 challenger 的 prompt，重新生成，直到题目满足"可学习"标准。

这个循环的关键不是让题更难，而是让题"刚好能学"。在两个任务上它做了方向相反的事：

在 CS 任务上，agent 的初始尝试通常是论文的高层概括题，4B 模型轻松答对。
经过平均 6.6 轮迭代，judge 反馈推动题目转向论文中的具体算法步骤、消融实验细节和数值论证——弱模型得分从 0.677 降到 0.458，强模型从 0.696 升到 0.772，gap 从 0.02 拉到 0.31。
用这批数据做 RL 训练后，4B 模型在 agentic 测试集上从 0.366 提升到 0.632，而用 CoT 数据训练只到 0.500（Table 2）。

在法律任务上，方向完全相反。CoT 生成的题太难，弱模型大量全零。
agentic loop 把弱模型得分从 0.159 提到 0.283，更关键的是 rollout 标准差从 7.93 提到 12.63——这意味着同一个 prompt 的多次尝试之间终于有了得分差异，GRPO 才能计算出有效的 advantage。
loop judge 判定的 GRPO 适用性分布从 CoT 的 4.8% high / 45% low 变成了 agentic 的 52% high / 2% low。
训练后，4B 模型在 PRBench-Legal 上得分 0.441（GPT-5 评分），超过了用 CoT 数据训练的 0.377，甚至超过了未做 RL 的 397B 模型的 0.404（Table 4）。

进一步，论文把"数据科学家"agent 本身也拿来优化（meta-optimization）。用一个进化式搜索框架迭代修改 agent 的 prompt 代码，同样用"能否制造有效区分弱强模型的数据"作为选择标准。
126 次接受迭代后，验证通过率从 62.1% 升到 79.6%。优化器自动发现了几个反直觉的改进，比如取消 rubric 中的负权重项——理论上看惩罚错误好像有帮助，实际上会破坏强模型得分。

这些结果都是在固定模型组合下得到的（weak: Qwen3.5-4B, strong: Qwen3.5-397B, judge: Kimi-K2.6），换模型组合效果是否一致尚未验证。
论文也提到 agent 有"作弊"倾向，比如试图修改弱模型的 prompt 让它变弱，需要额外约束来防止。

* 我能带走什么

以后看到合成训练数据，我先不急着判断"质量高不高"或"难度大不大"，而先问一个问题：
这批数据对目标模型是否提供了可学习的梯度信号——弱模型是全零（太难）还是已经接近满分（太容易），同一个 prompt 的多次 rollout 之间有没有足够的得分方差？

这个判断可以直接用在数据筛选上：与其用静态指标过滤，不如先把候选数据跑一轮 rollout，看目标模型的得分分布是否落在"可攀爬区间"。
