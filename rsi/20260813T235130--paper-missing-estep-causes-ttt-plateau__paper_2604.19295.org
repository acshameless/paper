#+title:      漏掉后验校准，自训练必然停滞
#+subtitle:   TEMPO: Scaling Test-time Training for Large Reasoning Models
#+source:     https://arxiv.org/abs/2604.19295
#+authors:    Qingyang Zhang, Xinke Kong, Haitao Wu, Qinghua Hu, Minghao Wu, Baosong Yang, Yu Cheng, Yun Luo, Ganqu Cui, Changqing Zhang

* 速读

测试时训练（TTT）让推理模型在无标签的测试题上继续自我提升，但现有方法（TTRL、EMPO）很快撞墙：给更多算力也不涨分，输出多样性还塌缩。
根因是它们只用模型自己生成的信号当奖励，随着策略变强，奖励信号自我强化、越漂越远。TEMPO 把 TTT 重新表述为 EM 算法：现有方法只做了 M-step（策略优化），漏掉了 E-step（用有标签数据校准 critic）。
补回这一步，奖励信号被周期性锚定到外部监督上，训练就能持续几百步不塌。

* 它到底在解决什么

一个反常现象：你给推理模型喂无标签的测试题让它自我提升，它一开始确实涨，但很快就平了——给更多算力也不动。更糟的是，输出越来越趋同：pass@k（多次采样能覆盖正确答案的比例）不升反降。

原来的做法（TTRL 用多数投票当伪标签，EMPO 用熵当奖励）有一个共同结构：奖励信号完全来自模型自己。模型越练越自信于某几种推理路径，这些路径就越容易在多数投票或低熵信号中胜出，反过来又强化同样的路径。
这是一个正反馈环：奖励信号随策略演化而漂移，离真实正确性越来越远。

问题不在于模型容量不够，而在于奖励信号没有被任何外部基准锚定。

* 它真正看见了什么

新判断：把测试时训练看成 EM（期望最大化）算法，现有方法都是只跑 M-step 的残缺版本——它们不断更新策略，却从不回头校准"什么算正确"的估计。漏掉的 E-step 正是奖励漂移的根源。

TEMPO 交替执行两步，形成一个被外部监督锚定的循环：

#+begin_example
    E-step: Critic 校准               M-step: 策略优化
  ┌────────────────────┐           ┌────────────────────┐
  │ 有标签数据 D_L       │           │ 无标签测试题 D_U     │
  │     ↓               │ 校准后的   │     ↓               │
  │ 用 ground-truth     │ ────────→ │ 生成回答 y ~ π_θ   │
  │ 训练 critic V_φ     │  critic    │ 用 V_φ 打分        │
  │     ↓               │           │     ↓               │
  │ critic 锚定在       │ ←──────── │ 更新策略 π_θ       │
  │ 外部监督上           │  新策略    │     ↓               │
  └────────────────────┘           │ 策略在难题上进化     │
          ↑_________________________________┘
              交替循环（奖励不漂移）
#+end_example

对比之下，TTRL / EMPO 的循环是：

#+begin_example
  生成回答 → 自生成奖励(多数投票/熵) → 更新策略 → 生成回答 → ...
               ↑_______________↓
          自强化环（奖励漂移）
#+end_example

关键区别：TEMPO 的 critic 周期性地回到有标签数据上重新校准，所以它的打分不会随策略漂移；而 TTRL / EMPO 的奖励完全来自模型自身，必然自我强化。

证据一：在 AIME 2024 上，TEMPO 把 OLMO3-7B 从 33.0% 提到 51.1%，Qwen3-14B 从 42.3% 提到 65.8%。
更关键的是多样性对比——以 Qwen3-14B 为例，TTRL 的准确率涨到 53.1%，但 pass@k 只有 56.7（比训练前的 Zero-RL 基线 69.1 还低），说明它的涨分是以牺牲多样性为代价的。
TEMPO 拿到 65.8% 准确率的同时 pass@k 维持在 73.3，甚至高于基线。这较稳地显示 TEMPO 的提升不靠收窄输出分布。

证据二：消融实验。把 critic 冻结（只训练一次、不再校准，即去掉 E-step），前 100 步和完整 TEMPO 一样涨，之后开始平。
因为静态 critic 和不断进化的策略脱节，打分不再准确。这较稳地显示 E-step 校准不是锦上添花，而是持续提升的必要条件。

适用范围：这些结果在数学、逻辑和 STEM 推理任务上跨模型族（Qwen3、OLMO3）显示。
但 TEMPO 需要同时维护 actor 和 critic 两个模型（显存翻倍），且 critic 校准依赖有标签数据 D_L——D_L 的分布和测试题差太远时，critic 的泛化可能受限。代码生成等需要执行验证的领域尚未验证。

* 我能带走什么

以后看到自训练系统在"给更多算力也不涨"，先不急着判断"模型容量到顶了"，而会先问：它的奖励信号有没有被周期性地锚定到外部监督上？如果没有，停滞可能不是能力问题，而是奖励漂移问题。

一个相关用法：在设计任何自强化循环（不只是 RL）时，检查"评估器"是否和"被评估对象"一起漂移。如果评估器完全依赖被评估对象的输出来校准自己，它迟早会失去判断力。
