#+subtitle:   GSEM: Graph-based Self-Evolving Memory for Experience Augmented Clinical Reasoning
#+source:     https://arxiv.org/abs/2603.22096
#+authors:    Xiao Han, Yuzheng Fan, Sendong Zhao, Haochun Wang, Bing Qin
#+venue:      arXiv 2026 (Harbin Institute of Technology)

* 速读

临床经验记忆系统按相似度做 top-k 检索时有两类致命错误：
一是"越界"——经验只匹配了部分条件，忽略了关键禁忌（如患者有风险因子 R 时某治疗禁用）；
二是"冲突"——几条经验各自相关但联合使用时互相矛盾，导致决策混乱。
GSEM 把每条经验拆成"适用条件 + 决策内容 + 极性（宜用/禁用）+ 质量分"，组织成双层图（经验内部决策流 + 经验间关联），检索时不是取 top-k 而是在图上遍历，
让 LLM 逐步判断每条经验是否适用、是否值得继续探索。任务完成后用反馈更新质量分和关联权重，不改经验内容本身。在两个临床推理 benchmark 上达到最高平均准确率，
治疗规划任务提升最明显。以后设计经验记忆，不能只存内容靠相似度检索，还要把适用边界和经验间关系显式编码成结构。

* 它到底在解决什么

一个临床 agent 积累了经验记忆——过去做对和做错的决策模式。遇到新病例时，它检索相似经验来辅助决策。但相似度检索有两个盲区。

论文用两个真实失败案例说明：

**越界失败**：患者有症状 X+Y 和风险因子 R。记忆里有一条经验"X+Y → 用 Treatment-A"。相似度检索命中了这条经验，但忽略了 R 的约束——R 存在时 A 是禁用的，应该用 C。
结果 agent 给了 A，错了。问题不在于经验内容不对，而在于检索没有检查这条经验的适用边界。

**冲突失败**：一个复杂外伤病例需要多步决策。
记忆里有两条经验：一条讲"急腹症手术步骤列举"，另一条讲"已有诊断时的治疗规划"。
两条各自相关，但联合使用时，第一条驱动立即列步骤，第二条接受伤情列表并推迟关键决策——两者没有联合使用价值，一起检索反而导致 agent 漏掉了最关键的手术决策（急诊胰十二指肠切除术）。

旧做法的根源：把经验存为独立文本条目，用 embedding 相似度做 top-k 检索。这种做法把"相似"等同于"适用"，把"各自相关"等同于"可以组合"——两个等价都不成立。

* 它真正看见了什么

经验记忆的检索错误，根源不在内容质量，而在缺失两层结构：经验内部的决策结构（条件→约束→行动→理由→结果）和经验间的关系结构（哪些可以组合、哪些冲突）。GSEM 把这两层显式编码成图，检索从"取最相似的 k 条"变成"在结构化经验空间中找一组适用且可组合的经验"。

关键区别在遍历环节：传统 top-k 一次性返回 k 条经验，不检查适用性也不检查组合性。GSEM 的图遍历让 LLM 在每一步都做判断——当前经验的条件是否匹配？沿这条边走是否有联合使用价值？这使得检索从"批量取相似"变成"逐步验证适用性和组合性"。

经验被形式化为四元组（条件, 内容, 极性, 质量分）。极性区分"宜用"（Indication，成功模式）和"禁用"（Contraindication，失败模式）。禁用经验的条件被显式存储，检索时可以检查当前病例是否触发了某条禁用条件——这正是越界失败的解药。

经验间的边权重 W 由四种相似度初始化（实体重叠、推理结构相似、联合使用价值、任务类型一致），然后通过任务反馈在线校准：反复共同出现在正确决策中的经验对，W 被加强；反复出现在错误决策中的，被削弱。这解决了冲突失败——没有联合使用价值的经验对，W 在进化中下降，遍历时就不会被一起选中。

证据方面，在 MedR-Bench 上用 DeepSeek-V3.2，GSEM 治疗规划准确率 94.59%，比最强 baseline A-Mem 的 92.57% 高约 2 个点。提升在治疗规划上最明显——这恰好是需要多步组合和边界检查的任务。自进化仅 50 次更新后，诊断错误从 19 降到 9，治疗错误从 8 降到 4；Q 分布变得更极化（好经验分更高、差经验分更低），W 分布变得更有选择性。这些结果在两个 benchmark、两个 backbone 上一致，较稳地显示了结构化检索的收益。

一个值得注意的发现：把检索器从 671B 换成 35B 模型，性能几乎不降（Qwen 检索 + DeepSeek 生成反而最好）。这说明图结构本身承担了大部分检索判断，降低了对检索器能力的要求——结构化检索比相似度检索更"省脑子"。

但结果有边界。在 MedAgentsBench 的部分子集上提升不明显，作者归因于预训练数据污染——模型已见过类似题，参数知识主导，外部经验的边际收益被稀释。检索策略依赖 LLM 引导的离散动作（COLLECT/EXPLORE/STOP），对 prompt 敏感，路径选择有非确定性。实验在公开 benchmark 上用自动评测，未覆盖真实临床工作流中的交互式决策和纵向随访。

* 我能带走什么

以后看到经验记忆系统只用相似度做 top-k 检索，先不急着判断"检索质量不够"或"经验不够多"，而先问两个问题：经验的适用边界在哪里显式编码了？经验之间能不能组合使用，这个信息在哪里编码了？如果两者都缺失，检索错误很可能不是"没找到"而是"找到了但越界或冲突"。

一个直接用法：设计经验记忆时，给每条经验加一个"适用条件"字段和一个"禁用条件"字段，检索时先做条件匹配再决定是否使用。不需要完整图结构，仅这一步就能避免大部分越界错误。
