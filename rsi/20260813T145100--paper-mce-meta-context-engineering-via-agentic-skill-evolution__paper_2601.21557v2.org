#+subtitle: Meta Context Engineering via Agentic Skill Evolution
#+source: https://arxiv.org/abs/2601.21557v2
#+authors: Haoran Ye, Xuning He, Vincent Arak, Haonan Dong, Guojie Song
#+venue: Peking University (Preprint)

* 速读

现有的上下文工程（CE）方法都靠人手写的工作流——生成-反思-策展循环、预定义的上下文模板——这些固定脚手架把优化空间限制在人类直觉能想到的子空间里。
MCE 把 CE 重新定义为一个双层优化问题：元层 agent 进化"怎么学上下文"的技能，基座层 agent 执行这些技能、用代码和文件系统自由地构建上下文。技能和上下文共同进化，用简单的 (1+1)-ES 驱动。
五个领域、四个 LLM 上，MCE 比 SOTA CE 方法平均提升 16.9%，训练快 13.6 倍，rollout 少 4.8 倍，上下文还能从强模型迁移到弱模型时掉得更少。

* 它到底在解决什么

LLM 的推理效果高度依赖推理时上下文的质量。上下文工程（CE）就是优化这些输入的学科——不调权重，靠改上下文来提升下游表现。优势明显：可解释、高效、模块化、不会灾难性遗忘。

但现有 CE 方法有一个结构性瓶颈：它们都依赖人手写的 agentic harness。

在上下文表示层面，不同结构各有取舍：案例轨迹保留丰富细节但泛化差；条目列表积累抽象洞见但结构扁平；图层级记忆灵活但延迟高。
在上下文优化层面，两种偏见同样致命：GEPA 这类 prompt 重写方法偏向简洁，把细节压成高层规则，在需要深度领域知识的任务上失败；ACE 这类累加策展方法偏向冗长，逐实例优化、只做局部更新，导致上下文膨胀和噪声积累。

问题的本质是：
没有单一的手写 harness 对所有任务最优。GEPA 的简洁在简单任务上好，ACE 的反思在需要深度抽象的任务上好，ICL 的原始示例在训练-测试分布接近的任务上好。
人手写的脚手架把 CE 锁死在一个狭窄的设计子空间里，无法发现任务最优策略。

MCE 要回答的问题是：能不能不靠人写 harness，让 agent 自己学会"怎么工程化上下文"？

* 它真正看见了什么

** 1. 把 CE 拆成双层优化：学什么 vs 怎么学

MCE 的核心形式化是把上下文函数 c(x) = (F_k ∘ ... ∘ F_1)(x; ρ) 的优化分成两层：

- 内层（基座层）：给定一个技能 s，执行它来产生上下文函数 c_s。这是"学什么"。
- 外层（元层）：搜索能产生最优验证性能上下文的技能 s*。这是"怎么学"。

这个解耦类比于 ML 中把学到的参数和模型架构/训练算法分开——只不过 MCE 在更高抽象层操作，LLM 已经冻结。
技能 s 是一个可执行规范：一个文件夹，包含方法论描述（自然语言）、可执行脚本（Python）、上下文模板、验证协议、动态上下文算子。agent 可以自由组合这些组件。

它是一个灵活的、审议式的过程——agent 推理跨任务规范、历史 CE 轨迹和性能指标，综合出新技能。

分析进化出的技能发现三个技术优势：
(1) 动态调整自主性和粒度——学到的技能会根据需要指定刚性工作流或完全授权；
(2) 按任务复杂度和模型容量定制上下文详细度——简单任务或小模型给简洁规则，否则给详细解释；
(3) 有效监控训练-验证信号、检测过拟合、引导技能进化走向泛化。

** 3. 基座层：完全 agentic 的上下文优化，上下文就是文件和代码

基座层 agent 拿到技能后，在一个工作区里执行：技能文件夹、上一轮最优上下文（热启动）、训练 rollout 结果、可选的工具函数。
agent 用标准工具集 {Read, Write, Edit, Bash, Glob, Grep, TodoWrite} 操作文件系统来产生上下文。

上下文不是预定义 schema 的条目列表，而是一组文件和代码——静态组件（知识库、决策规则、示例）和动态算子（检索、过滤、组合逻辑）。代码和文件表示不施加任何结构约束，允许任意计算过程来生成和操作上下文。

这跟 ACE 的 rigid generation-reflection-curation 工作流形成鲜明对比。ACE 是 SOTA CE 方法的一个"点"，MCE 是包含它的"流形"。

** 4. 实验结果：全面碾压，而且不是靠模型更强

五个领域（金融 FiNER、化学 USPTO-50k、医学 Symptom2Disease、法律 LawBench、AI 安全 Aegis2.0），四个 LLM，离线和在线两种设置：

- 离线：MCE 在所有五个 benchmark 上排第一，平均相对基座模型提升 89.1%，ACE（第二名）70.7%。
- 在线：MCE 平均提升 74.1%，ACE 41.1%。
- 相对 SOTA CE 方法提升 5.6-53.8%，均值 16.9%。
- MCE 增强的通用 LLM 超越领域专用模型：LawBench 上 MCE 达 0.70 F1，最佳法律专用模型 0.56；Aegis2.0 上 Qwen3-8B + MCE 达 0.80 F1，超过专用安全模型 Llama Guard 3 8B 的 0.72。

关键消融排除了模型混淆：MCE 用 MiniMax M2.1 做 agentic model，把 ACE 的 reflector/curator 也换成 M2.1 后，ACE 性能反而下降（67% vs 70%），上下文更膨胀（114K vs 79K tokens）。
MCE 的优势来自方法论设计，不是模型能力。

** 5. 上下文适应性：不受简洁或冗长偏见束缚

GEPA 倾向简洁（~1-2K tokens），ACE 倾向膨胀（5 轮后达 80K tokens）。
MCE 学会按任务需求灵活调整：FiNER 上最有效的两个上下文分别是 1.5K 和 20K tokens，LawBench 和 USPTO50k 上分别达 44K 和 86K tokens。

上下文效率：FiNER 上同等长度（~1.5K tokens），MCE-S 达 73% 准确率 vs ACE 的 65%；MCE-L 用 20K tokens 达 75%，超过 ACE 5 轮优化后的 70%（79K tokens）。
原因：(1) agent 保持全局视角，能重构和精炼已有知识而非盲目追加；(2) 批量处理训练 rollout，聚合跨样本反馈后再更新上下文。

** 6. 迁移性和训练效率

强→弱迁移：DeepSeek-V3.1 训练的上下文迁移到更小模型时，MCE 的性能退化始终低于 ACE（17.1-23.6% vs 23.6-48.3%）。ACE 的迁移上下文有时甚至让小模型比零样本更差。
原因：MCE 的紧凑上下文缓解小模型长上下文处理困难；批量级优化产生结构良好的上下文，不过拟合训练模型的错误模式。

训练效率：FiNER 上 MCE 5 轮 1.9 小时 vs ACE 25.8 小时（13.6 倍加速）。MCE 只需 450 rollout 达 95% 训练准确率，ACE 2169 rollout 峰值才 94%（4.8 倍 fewer rollout）。

** 7. 技能进化的案例：从"建全面上下文"到"知道何时该停"

Symptom2Disease 上最引人注目的发现：最优技能引入了显式停止准则。技能从迭代历史中学到"88% 验证准确率、1% gap 已接近最优"，
于是设定：验证模式 < 3 个、训练准确率 > 90%、估计 gap > 1.5%、不可约错误 > 40% 时停止。这是元学习洞见：知道何时停止和知道添加什么一样重要。

LawBench 上技能从"模式学习"转向"结构分解"：技能发现即使简化的规则也会导致记忆化，于是引入"事实→行为→罪名"的结构化案件分解框架，把上下文从 88KB 压缩到 30KB，同时减少过拟合。

* 我能带走什么

- **"技能"是一个比"提示词"或"工作流"更高阶的进化抽象。** EUREKA 进化奖励函数代码，ReEvo 进化启发式算法，MCE 进化的是 agent 技能——一个包含指令、脚本、资源的完整文件夹。
这个抽象的优势是能无缝共同进化不同层级的解决方案（方法论 + 代码 + 模板 + 验证），而不是碎片化地优化单一组件。这个范式可以推广到 CE 之外的其他 agentic 能力。

- **双层优化 = 把"学什么"和"怎么学"解耦。** 这跟 ML 中参数 vs 架构的解耦完全同构。MCE 的贡献是把这种解耦提升到 CE 层面：上下文函数是"学到的参数"，技能是"架构和训练算法"。
这个框架可以启发其他需要"学会学习"的场景。

- **完全 agentic 的上下文优化（文件 + 代码）比预定义 schema 强得多。** 给 agent 编程工具和文件系统访问，让它自由决定上下文的结构和优化流程，比人手写 generation-reflection-curation 循环好。
ACE 的 playbook 只是 MCE 设计空间中的一个点。这跟 EUREKA 的"环境源代码即上下文"异曲同工：不要限制表达空间，给 agent 最大自由度。

- **批量化是效率的关键。** MCE 快 13.6 倍的核心原因不是模型更强，而是批量化：agent 一次性分析大量训练 rollout，聚合反馈后更新上下文，而不是像 ACE 那样逐实例优化。
全局视角 + 批量聚合 = 更连贯、更不冗余的上下文。

- **进化出的技能会自己学会"何时停止"。** Symptom2Disease 的案例最精彩：技能进化出停止准则，认识到"88% 已接近最优，剩余错误不可约"。这不是人教的，是 meta-agent 从验证信号中学到的。
这暗示进化搜索能发现人类不会主动编码的元认知策略。

- **边界：MCE 擅长领域知识获取和模式匹配，不擅长推理密集型任务。** 论文坦承，对于需要迭代试错、错误纠正、系统反思的推理任务，现有手写 harness 已经够好。
MCE 的优势在于"学到的技能能有效捕获数据特征并组织领域特定结构"。
另外，MCE 在超长复杂轨迹的 rollout 上可能挣扎，因为批量级 CE 难以做细粒度信用分配——但这受限于底层 agent 模型能力，会随 agentic 模型进步而缓解。
